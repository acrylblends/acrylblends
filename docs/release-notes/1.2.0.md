# 1.2.0

`acrylblends` and `create-acrylblends` 1.2.0. An app is now a repository from its first minute and a set of plugin folders, each with its row in
`blend.yaml`; an app can be saved as a snapshot and checked against it; `create --from` makes an app from a registry blueprint that carries its own name,
lock and first commit; and the scaffold, the upgrade and the gates for the ACRYL frame are in place for the day its packages are on npm.

## Added

- **A new app is a git repository.** `init` (and `create`) runs `git init`, adds the scaffold and commits it as "Initial commit from acrylblends", with the
  person's own git identity when there is one and the scaffolder's otherwise. A folder that already is a repository, or a machine without git, is left alone.
- **A feature is a plugin folder plus its row.** Every template (blank, nodejs, chat, notes, todo, agent) composes `blend.yaml` the same way: a row that
  names `plugins/<name>/` loads that folder, and the extensions row never starts it twice. The blank template gains the home plugin, so its page shows the
  widgets of the app's plugins under the app's name.
- **Two skills in every app.** `acryl-app` (the rows, `src/app.ts`, `src/routes.ts`, the `plugins/` folder, the door verbs, what done means) and
  `cordis-plugin` (adding a feature as a plugin: `name`/`inject`/`apply`, routes, state cells, the row) are written to `.claude/skills` and `.agents/skills`,
  so a coding agent started in the app folder finds them.
- **Snapshots: `npm run snapshot capture | verify | apply`.** `capture` gives every plugin folder of the app its row and locks the app in `blend.lock.json`
  (the manifest's digest and each folder's); `verify` checks the app against the lock and names what changed; `apply` brings another snapshot's folders and
  rows into this app, refusing the whole apply when a folder here differs from the locked one.
- **Widgets look finished without styles of their own.** The home page puts a plain card look (light or dark with the system) before the widgets, so a
  widget written as plain HTML (lists, forms, buttons) no longer renders as browser defaults.
- **The production Assistant** (`ACRYL_ASSISTANT=on`): the app's agent stays in production as a helper that uses the app for a visitor (it looks and acts
  through the page only) and cannot change it.
- **Feedback from the people who use the app** (`acrylblends add feedback`): a Feedback button on every page with an element picker, or "Nothing specific"
  for the page; the screenshot is the visitor's choice; notes are checked, rate-limited and kept in the app's home.

## create-acrylblends

- **`--from <registry id>` makes an app that is its own.** The starter's name becomes the new app's where the scaffold wrote it (the README's and agents'
  headings, the skills' descriptions, `APP_NAME`, the DSH profile, both names in `package-lock.json`), never in a route or a sentence. A curated blueprint
  whose manifest carries a display name ("Productivity Hub") is renamed from its package name. The manifest gets the new id, private and unlicensed.
- **The lock stays true.** `blend.lock.json`'s origin takes the new id, version and manifest digest, so `npm run snapshot verify` passes on the new app.
- **It starts as a repository**, with the same first commit as `init`.
- `--registry` takes a registry folder written as a bare path, and a folder without `index.json` is one line naming it.

## Fixed

- A new blank app's first screen in a browser is a page (the app's name and what to edit), not the browser's JSON viewer; other clients still get the JSON
  hello. The blank page paints its own background, so its text is readable on a dark system.
- A blank app's `npm test` passes while the frame runs it and after a feature row is added.
- `acrylblends upgrade` never writes or refuses over an edited `src/routes.ts` (the app owns it from its first edit), says when the frame cannot show the
  app because that file does not export `FRAME_MOUNT_PREFIX`, and updates a copy the app never edited, so an upgraded app answers in the frame at `/app`
  (it answered 404). It tells the lines `acrylblends add` wrote into `src/app.ts` from the owner's own: an app with an added plugin upgrades with no flag,
  an owner's line stops the upgrade and is named.
- Windows: the gates spawn `npm.cmd` and the door's `.cmd`, find Chrome in its Windows locations, and read CRLF rows.

## The ACRYL frame (not on npm yet)

`init --desktop` and `upgrade` can put an app inside the ACRYL frame (the chat, Files, Changes, Versions, Settings and the app on the canvas). The frame's
packages are not published yet, so from npm an app runs on the framework alone and says so; from a checkout, `ACRYLBLENDS_FRAME_PACKAGES` (see
`scripts/lib/ide-specs.mjs`) installs them, and now installs the checkout's framework with them, so the frame and the app share one copy (with two, a
wrong method on a private route answered 500 instead of 405 with its `Allow`). `docs/plans/frame-publish.md` is the list and the checks for publishing them.

## Upgrading

`npx acrylblends upgrade` in an app made before 1.2.0, then `npm install`. Your own files are left as they are; for the snapshot verbs, the skills and the
plugin-row layout, compare with a fresh app (`npx acrylblends init fresh --template blank`).
