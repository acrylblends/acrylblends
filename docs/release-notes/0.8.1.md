# 0.8.1

The door's plugin verbs work in every web template.

## New

- **`extensions` in `nodejs`, `notes` and `chat`.** These templates now mount the `extensions` plugin (and its `sandbox`), so `.acryl/bin/acryl plugin list|add|remove|reload` work in them as they do in the `agent` template: an agent working in the folder can add a plugin to the running app, take it out again, or swap a provider (see [Bring your own tool](../framework/guides/bring-your-own-tool.md)), and `brief` no longer says "Live plugins: unavailable". What is installed lives in `plugins/`, next to the plugins copied from the library (`plugins/library.json` lists those, so they are not installed twice).
- Development only, like the door: the `extensions` row is left out with `NODE_ENV=production`, so a deployed app cannot be changed while it runs.
- `verify:scaffolder` adds a plugin live in each web template, calls its route and removes it, through `.acryl/bin/acryl`.

## Things to know

- `create-acrylblends` 0.3.1 depends on `acrylblends` `^0.8.1`. An app made with 0.8.0 does not change: add `extensions` with `npx acrylblends add extensions`, a row `extensions` before the `server` row of `blend.yaml`, and `extensions` in the registry and the `extensions: { sources: [...] }` config of `src/app.ts` (copy them from a new app).
