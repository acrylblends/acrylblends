# 0.7.0

Pages are written in `.tsx`, as the framework docs show. The apps `acrylblends init` and `create-acrylblends` make now run `.tsx` on Node.js with no build step.

## New

- **`acrylblends/node-server/register`** (95 subpaths now): a Node.js module hook, `node --import acrylblends/node-server/register app.tsx`, that compiles `.tsx` and `.jsx` files with the app's own `typescript` (`react-jsx`, the `jsxImportSource` of the nearest
  `tsconfig.json`, `acrylblends/jsx` by default) and leaves every other module to Node. The output carries an inline source map, so an error stack names the `.tsx` line. Without `typescript` it says what to install.
- **The templates use it.** In a `create-acrylblends` `nodejs` app, `npm run dev`, `start` and `test` run with the hook, `tsconfig.json` sets `jsx: react-jsx`, and the app has a `.tsx` page (`src/page.tsx`, served at `/about`) with a test that
  renders it and a test that an error in it names the `.tsx` line. In the Blend templates (`blank`, `todo`, `agent`) the scripts use the vendored hook (`src/plugins/acryl-node-server/src/register.ts`); the JSX runtime is the vendored one through a
  `package.json` `imports` entry (`#acryl-jsx`); the `blank` template has a `.tsx` page at `/about` with the same two tests.
- **The desktop shells register the hook before they load the app,** so an app with `.tsx` pages runs in the window too.
- **`AGENTS.md` makes `.tsx` the normal path** in both kinds of app, with `jsx(tag, props, ...children)` as the build-free alternative.

## Things to know

- A command that starts the app without the scripts (a bare `node src/main.ts`) cannot load a `.tsx` file: use `npm run dev` or `npm start`, or add `--import` as the scripts do.
- `create-acrylblends` 0.2.0 makes these templates and depends on `acrylblends` `^0.7.0`.
