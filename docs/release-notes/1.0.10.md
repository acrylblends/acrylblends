# 1.0.10

A production install no longer carries vitest.

## Fixed

- **`acrylblends` no longer declares `vitest` as a peer dependency.** It was declared (optional) for the two conformance suites a provider of a port passes, `acrylblends/db/conformance` and `acrylblends/kv/conformance`; pnpm resolves an optional peer wherever the workspace has the package, so `pnpm deploy --prod` of an app pulled vitest, vite, rolldown, lightningcss and their native files into the production closure (about 30 MB, and files of the wrong platform for an archive built on another system). The suites import `vitest` from the provider's own project, which has it as a dev dependency because it runs them; nothing else the package ships imports it (`acrylblends/testing` never did).
- A new gate, `pnpm run verify:vitest-peer`, checks the packed package declares no vitest, that `pnpm install --prod` of a project that depends on it has no vitest, vite, rolldown or lightningcss in its closure even with vitest in the workspace beside it, and that a provider's project with its own vitest still runs the kv conformance suite from `acrylblends/kv/conformance` under pnpm. It fails on 1.0.9.

## Upgrading

Nothing to change for an app. A provider's tests keep `import { describeKvConformance } from 'acrylblends/kv/conformance'`; the project needs `vitest` as its own dev dependency (it already does, to run them). Under `hoist=false` or Yarn PnP, which do not let a package reach a dependency it does not declare, the conformance suites cannot see vitest: use the vendored copy (`npx acrylblends add kv --suite`), which imports it from the app.
