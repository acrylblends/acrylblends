# 1.0.10

A production install no longer carries vitest.

## Fixed

- **`acrylblends` no longer declares `vitest` as a peer dependency.** It was declared (optional) for the two conformance suites a provider of a port passes, `acrylblends/db/conformance` and `acrylblends/kv/conformance`; pnpm resolves an optional peer wherever the workspace has the package, so `pnpm deploy --prod` of an app pulled vitest, vite, rolldown, lightningcss and their native files into the production closure (about 30 MB, and files of the wrong platform for an archive built on another system). The suites now run on the vitest the provider's test hands them as a third argument, so the package imports no vitest at all (`acrylblends/testing` never did) and a suite can never see a second copy of vitest that is not the one running the test.
- A new gate, `pnpm run verify:vitest-peer`, checks the packed package declares no vitest and no file of it imports vitest, that `pnpm install --prod` of a project that depends on it has no vitest, vite, rolldown or lightningcss in its closure even with vitest in the workspace beside it, and that a provider's project with its own vitest runs the kv conformance suite from `acrylblends/kv/conformance` under pnpm. It fails on 1.0.9.

- **`window list` names the path a window was opened on** until its page reports its own address (it showed an empty path for a window still loading), and the timeout text adds "a page busy running a long script" to the causes it names.

## Upgrading

Nothing to change for an app. **A provider's test that imports `describeKvConformance` or `describeDbConformance` from the package now passes vitest as a third argument:**

```ts
import * as vitest from 'vitest'
import { describeKvConformance } from 'acrylblends/kv/conformance'

describeKvConformance('my-provider', open, vitest)
```

Without it the call throws, saying what to pass. The copy that `npx acrylblends add kv --suite` (or `db --suite`) puts in an app, and the plugins' own suites in this repository, are unchanged: they import vitest from the app, and take two arguments.
