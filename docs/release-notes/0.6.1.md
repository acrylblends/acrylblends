# 0.6.1

`acrylblends add desktop` now works in a plain Acryl app (the `nodejs` template of `create-acrylblends`), and a new app depends on the release that created it.

## Changed

- **The desktop shell for a plain Acryl app.** `acrylblends add desktop` in an app that has no Blend plugins adds `src/plugins/desktop-web`: it imports the app (`src/app.ts`, `export default app`), serves `app.fetch` on `127.0.0.1` with a free
  port through `acrylblends/node-server`, opens one window on that address and, when the window closes, stops the server and exits. The same rules as for a Blend app: `electron` is a development dependency and only `src/plugins/desktop-web`
  imports it, one window per app (single-instance lock), Electron's user data inside the app folder (`.acrylblends/electron`, added to `.gitignore`), nothing left running. In a Blend app, `add desktop` adds the `desktop` plugin as before.
- **`create-acrylblends` 0.1.2 stamps the framework version at create time.** The `nodejs` and `bun` templates depend on `^<the acrylblends version this create-acrylblends was released with>`, so `npm create acrylblends@latest` followed by
  `npx acrylblends add desktop` runs the release that has it (0.6.0 shipped with 0.5.0 stamped, which could not).
