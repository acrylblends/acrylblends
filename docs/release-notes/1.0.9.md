# 1.0.9

Hardening after the first walks of 1.0.8's WebSocket channel, and a panel bug a CI run found.

## Fixed

- **A message typed as the page loads is no longer dropped.** The panel asks the server for the latest run when a page loads, and over its socket "there is none" takes a round trip; a message typed in that moment found the panel believing it was busy following a run, and was ignored (the text stayed in the box, nothing was asked). A panel is busy only once there is a run to show. A real-browser case delays that answer and fails on 1.0.8's client; it is how a CI run (Node 26, a slow runner) lost a message.
- **The "Working... m:ss" timer counts from the run's start**, not from when the page loaded (a page that loads during a long run showed 0:05 on a run 25 minutes old).
- **A look right after a navigate or reload waits for the page to register again** (up to two seconds) instead of failing with a timeout, and a read-only call that no page acknowledged gets one more try when a page registered while it waited.
- **The "no page answered" message names the real causes** (a background tab, a page still loading, a page holding the browser's six connections with event streams of its own) so an agent no longer reloads and resizes windows to chase one that does not apply.
- **`window list` shows each window's place** (`1100x760@120,80`), and the real-Electron gate asserts that a window opened beside another does not stack on it (1.0.8's cascade).

## Upgrading

`npx acrylblends@latest upgrade` brings the door, the panel and the desktop shell.
