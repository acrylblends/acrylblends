# 0.8.0

Every new app is a Cordis app, and an agent working in the app's folder can look at the running page and act on it.

## New

- **Every template is a Cordis app.** `nodejs`, `notes` and `chat` are made by `acrylblends init`, like `blank`, `todo` and `agent`: `blend.yaml` lists the plugins that are mounted, every plugin is a folder in `plugins/`, `src/main.ts` starts the app, and `src/routes.ts` is the app's own plugin. The features are the same: a page and a client component (`nodejs`); accounts, sessions and notes in SQLite through the `db` port (`notes`); a streamed answer and its history (`chat`). `create-acrylblends` only calls `init` now, and `bun` is no longer a template (the framework still runs on Bun).
- **A bare template name works:** `npm create acrylblends@latest my-app notes`.
- **The door.** The running app writes `.acryl/bin/acryl`, a command that reaches only the app running from that folder: `brief`, `look` (the page as text with refs, including its visible text), `act` (click, type, select, press, scroll, wait), `plugin add|remove|reload|list`, and `tool list|call`. It is loopback only, has a per-run secret in `.acryl/door.json`, writes an audit log and shows an indicator with a stop button in the page. `.acryl/` is ignored by git. The door is on in development and off with `NODE_ENV=production` or `ACRYL_DOOR=off`. `AGENTS.md`, `CLAUDE.md` and the `app-guide` skill name the verbs.
- **The product test.** `scripts/verify-coding-agent.mjs --part2` has Claude Code, Codex and pi each build the same feature in a fresh app from the docs alone; then the gate reads it off the running page through `.acryl/bin/acryl look` in a real browser, restarts the app, installs and tests a fresh `git clone`, and checks that `git add -A` stages no secret. All three pass.
- **The agent panel** (opt-in, development only): `npx acrylblends add agent-panel` adds a chat panel to the running app. Say what you want; the app's own agent, or Claude Code, Codex or pi started in the app folder, builds it through the door, and the page reloads when a plugin was installed or removed, with no restart. See [Plugins](../plugins.md#agent-panel).
- **Bring your own tool.** One guide (`docs/framework/guides/bring-your-own-tool.md`) wraps an npm package as a provider of a port, passes the port's conformance suite and swaps it into the running app through the door. `acrylblends add kv --suite` (or `db`) copies the suite and `vitest`; `add` writes `package.json` imports (`#acryl-kv`, `#acryl-db`, ...) so your own provider imports the port by name, in tests, in the type-check and when installed live. Three agents followed the guide alone and swapped in a different tool.
- **Every template passes its own tests in Codex's default sandbox** (no network, no system temp folder): the tests run in process (`createApp(..., { listen: false })`) and the few that need a real connection skip with a printed reason. `verify:scaffolder` checks all six templates.
- **`clientModules` works inside a sub-app.** A `clientModules` (or any handler that reads `basePath(c)`) nested in an app that is mounted on the router answered 404 for every file, because the router dropped the nested base path (T024).

## Things to know

- The tests of the new templates need no temp folder and no port, so they run in an agent's sandbox: they keep throwaway homes in `.acrylblends/test`, call the app in process (`createApp(..., { listen: false })`), and skip the one test that starts the real server where listening is forbidden, printing why.
- One process at a time serves a folder's door. The templates' tests that start apps set `ACRYL_DOOR=off`.
- The `extensions` plugin (live `plugin add`) is part of the `agent` template; the web templates do not mount it yet.
- `create-acrylblends` 0.3.0 depends on `acrylblends` `^0.8.0`.
