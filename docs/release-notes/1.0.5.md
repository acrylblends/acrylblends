# 1.0.5

The app's own agent can drive the page with a real model, and a person's own routes can no longer break the agent template's tests.

## The app's own agent drives the page

- **The door's verbs reach a real model with their schemas.** The tools registry takes an optional JSON Schema per tool (`parameters`), the openai plugin sends it, and the door registers `door_look` and `door_act` with the schema MCP lists, so a model knows an `act` needs its `op`. With a DeepSeek key in the server's environment (`ACRYLBLENDS_MODEL_URL`, `ACRYLBLENDS_MODEL`, `ACRYLBLENDS_MODEL_KEY`) the panel's built-in agent looks at the open page and presses its buttons: no Codex or Claude login needed. Recorded in [the evidence page](../plans/door-build-and-check-evidence.md).
- **The agent template's default step budget is 12** (it was 6: looking, pressing and looking again used the six before the answer).
- **The agent panel's script is added to every HTML page the app answers**, including the pages of a plugin that loads at boot (it used the late-mount way and was missing after a restart). It uses `ctx.router.wrap`, like the door.

## The agent template's tests

- **`test/builder.test.ts` builds a plugin with a name and a path of its own** (`builder-probe-<random>`), not `/hello`. A route a person adds at `/hello` (the workshop's first route) shadowed the plugin the test installs, and the template's own `npm test` failed on 1.0.4. The packed-install gate now adds `/hello`, `/hi` and `/api` to the agent template's routes and runs its tests.

## Upgrading

`npx acrylblends@latest upgrade` brings the door, the router, the panel, the agent and the openai plugin of an existing app; an agent-template app's own `test/builder.test.ts` and `blend.yaml` are its own files (copy them from a fresh `npm create acrylblends@latest my-app agent` if a route of yours shadows the old test).
