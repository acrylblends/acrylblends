# 1.0.5

The first-run fixes from the workshop guide's walk on 1.0.4, and the app's own agent driving the page with a real model.

## The agent template

- **A new app from the `agent` template has the agent panel.** `npm create acrylblends@latest my-app agent` answers `/api/agent-panel/session` with no `add` step; `add driver-pty` and `add driver-acp` mount after the panel's row. (An agent-template app made earlier gets it with `npx acrylblends add agent-panel`.) The panel starts nothing in production.
- **`test/builder.test.ts` builds a plugin with a name and a path of its own** (`builder-probe-<random>`), not `/hello`. A route a person adds at `/hello` (the workshop's first route) shadowed the plugin the test installs, and the template's own `npm test` failed on 1.0.4. The packed-install gate now adds `/hello`, `/hi` and `/api` to the agent template's routes and runs its tests.
- **The default step budget is 12** (it was 6: looking, pressing and looking again used the six before the answer).

## The panel

- **The tool lines say what the tool is doing.** A coding agent started in the folder reports its own log; the panel showed the driver's name once per event ("codex, codex, codex"). It now shows the command (`codex: $ npm test`) or the sentence, drops the agent's bookkeeping (hooks, token counts, the output of a command that succeeded), and shows a failure; the app's own agent shows the tool and its arguments.
- **The panel's script is added to every HTML page the app answers**, including the pages of a plugin that loads at boot (it used the late-mount way and was missing after a restart). It uses `ctx.router.wrap`, like the door. A gate now checks the door's and the panel's scripts on a page of a plugin installed live, one loaded at boot, and one mounted as a row of `blend.yaml` ahead of both.

## The door and the app's own agent

- **The door's verbs reach a real model with their schemas.** The tools registry takes an optional JSON Schema per tool (`parameters`), the openai plugin sends it, and the door registers `door_look` and `door_act` with the schema MCP lists, so a model knows an `act` needs its `op`. With a DeepSeek key in the server's environment (`ACRYLBLENDS_MODEL_URL`, `ACRYLBLENDS_MODEL`, `ACRYLBLENDS_MODEL_KEY`) the panel's built-in agent looks at the open page and presses its buttons: no Codex or Claude login needed. Recorded in [the evidence page](../plans/door-build-and-check-evidence.md).

## Desktop

- **`npm run desktop` while `npm run dev` runs attaches to the running server** instead of failing with "another process serves the door": the window opens on the dev server found through `.acryl/door.json` (only a live process on a loopback address that answers), prints a line saying so, and closing the window leaves that server running.

## Upgrading

`npx acrylblends@latest upgrade` brings the door, the router, the panel, the agent, the openai plugin and the desktop plugin of an existing app. An agent-template app's own `test/builder.test.ts`, `blend.yaml` and `src/app.ts` are its own files: copy them from a fresh `npm create acrylblends@latest my-app agent` if a route of yours shadows the old test or you want the panel row.
