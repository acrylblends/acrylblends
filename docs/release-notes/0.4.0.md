# 0.4.0

The router and the node server are now the ACRYL framework's ported core: ordinary Web-standard `App` objects with the reference framework's routing,
middleware, validators and test suites, mounted on the router by a Cordis plugin. This release is breaking for every plugin that registered a route.

## Breaking changes

1. **Routes are an `App` mounted with `ctx.router.route(prefix, app)`.** `ctx.router.get`, `post`, `put`, `patch`, `delete`, `all`, `on`, `use` and `group` are gone,
   not kept as aliases. Build the whole app first: routes added to an app after it was mounted are not served.
2. **The handler context is the ported one.** `c.param('id')` is `c.req.param('id')`, `c.query(name)` is `c.req.query(name)`, the Web request is `c.req.raw`,
   `HttpError` is `HTTPException`, `validate`/`valid` are `schemaValidator`/`c.req.valid`, and `bodyLimit` takes `maxSize`. The full table is in
   [Migration from 0.3](../framework/cordis/migration-from-0-3.md).
3. **Transport facts are in `c.env.connection`** (peer address, port), read with `connectionOf(c)` or `getConnInfo(c)`.
4. **A server-sent stream is written by you:** `streamSSE(c, async stream => ...)` with `stream.writeSSE({ data, event, id })`; there is no automatic keep-alive.
5. **A live plugin imports `App` from `acryl-router`.** The agent's plugins, written while the app runs, can use the app's own copy of the router
   (`import { App } from 'acryl-router'`; also `acryl-router/middleware` and `acryl-router/helpers`). The model prompt and the builder write plugins this way.

## Migrating a route

```ts
// 0.3.0
export const inject = ['router']
ctx.router.get('/hello', (c) => c.json({ text: 'Hello' }))

// 0.4.0
import { App } from 'acryl-router'   // in a generated app: './plugins/acryl-router/src/index.ts'
export const inject = ['router']
ctx.router.route('/', new App().get('/hello', (c) => c.json({ text: 'Hello' })))
```

The mount belongs to the plugin that made it and is removed when that plugin is unloaded. Public paths do not change.

An app made with 0.3.0 keeps working, because you own every copied line. To take 0.4.0, create a new app with `npx acrylblends init my-app --template blank`
(or `todo`, `agent`) and move your routes over with the migration page open.

## Changed

- **The core is a port.** `acryl-router` and `acryl-node-server` carry the reference framework's source with its test suites (about 3,100 tests run in this repository),
  vendored from ACRYL commit `df79b188` as they are. `pnpm run verify:framework` fails when a copy was edited.
- **Generated apps type-check with `lib` ES2024 plus DOM** (the Web types the core is written against), `strict` on, and without `noUncheckedIndexedAccess` and
  `exactOptionalPropertyTypes`. This is the profile `acryl-router` publishes as `tsconfig.app.json`.
- **The `todo` template is ACRYL's updated reference app:** validation, a body limit, an ordered event stream, a file that keeps the list across restarts.
- **An app no longer receives a plugin's tests.** A library plugin's `omit` takes globs (`**/*.test.*`), so the vendored framework plugins arrive without their
  colocated test files.
- **The agent template type-checks the plugins the agent writes**, including their `acryl-router` imports.

## Unchanged

The templates `blank`, `todo` and `agent` and `--template`; the plugin names (`acryl-router`, `acryl-router-http`, `acryl-node-server`, `acryl-state`, `acryl-inspect`);
`instance`, `settings`, `extensions`, `builder`, `agent`, `openai`, `sandbox`, `tasks`, `manifest` and `save`; `blend.lock.json` (format version 3) and the registries;
Node 22.19 or newer.
