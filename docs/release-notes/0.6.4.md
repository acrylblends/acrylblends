# 0.6.4

The package no longer carries the upstream project's name inside longer identifiers, it is a third smaller, and an agent writing a page with `acrylblends/jsx` is told how.

## Changed

- **The rename is complete.** The framework core had kept the upstream name inside a few longer names (the cache-key parameters, the portal element constant, the streaming flag, the static-site header). They are renamed in ACRYL and vendored here from commit `5e94dab1`.
  A new release gate, `pnpm run verify:tarball`, packs both packages and fails on the name in any file or path (LICENSE files excepted; only the whole English words honor, honour and their forms are allowed), in camel, snake, screaming and kebab styles.
- **A third smaller.** The package ships only what an app can receive: the vendored plugins' tests and colocated test files stay in the repository. `acrylblends` goes from 878,916 to about 590,000 bytes packed and from 772 to about 615 files.
- **More of the framework:** `acrylblends/jsx-renderer` and `acrylblends/ssg` (94 subpaths in all), and their docs pages are no longer marked "not yet available".
- **Writing JSX in an app.** Node.js strips types and does not compile JSX syntax, so the app's `AGENTS.md` now says to write the call JSX compiles to (`jsx(tag, props, ...children)`) and maps `acrylblends/jsx` to the vendored files in a Blend app. Live plugins and the agent template resolve `acrylblends/jsx`
  (and its runtimes and `streaming`). The JSX docs page explains the same, with a checked example.
