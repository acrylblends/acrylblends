# 0.7.4

Hosting adapters, and templates from other people's repositories.

## New

- **Hosting adapters.** `acrylblends/aws-lambda` (API Gateway REST and HTTP APIs, Application Load Balancer, Function URLs, VPC Lattice, response streaming), `acrylblends/lambda-edge`, `acrylblends/cloudflare-workers` (client address, WebSockets), `acrylblends/cloudflare-pages`, `acrylblends/vercel`, `acrylblends/netlify`, `acrylblends/service-worker` and `acrylblends/bun` (static files, WebSockets, client address). 103 subpaths now. Each is the upstream adapter ported with its tests; the release check calls each handler with the platform's own events (an API Gateway v1 and v2 event, an ALB event, a CloudFront event, a Pages event context, a fetch event), runs a Worker in `workerd` with `wrangler dev --local`, and runs the Bun adapter on Bun. None has been deployed to a platform account by the ACRYL team: try a first deploy on a test project. A getting-started page for each is in the docs, linked from Other runtimes.
- **Templates from a repository or a package.** `npm create acrylblends@latest my-app github:owner/repo[#ref]`, `@scope/name[@version]` or a packed `.tgz`. The source is downloaded as a tarball (never cloned) or packed with `npm pack --ignore-scripts`, and must hold an `acryl.template.json` (`name`, `description`, optional `plugins`). It is checked for secrets before the folder is created. Nothing of the template is installed or run: install scripts it defines are listed, and `--install` prints what will run first. See the create-acrylblends guide.

## Fixed

- Importing `acrylblends/bun` on Node no longer throws; the Bun adapter reads `Bun` when it writes a file, not when the module loads.

## Things to know

- `create-acrylblends` 0.2.4 depends on `acrylblends` `^0.7.4` and on `@webboxes/app-persistence` for the secret check.
