# 0.7.7

`kv`: named JSON documents for an app too small for SQL.

## New

- **`acrylblends/kv`, `acrylblends/kv/json` and `acrylblends/kv/db`** (108 subpaths). `openKv({ path })` from `acrylblends/kv/json` opens one JSON file and returns `{ kv, close }`. `kv` has `get`, `set`, `update`, `delete` and `list(prefix)`, every call a promise, values JSON. `update(key, change)` is atomic, and `change` is a plain synchronous function (an `async` one is a type error and is rejected with a message that says what to do). Every write is a whole new file written beside the old one and renamed over it, so a crash leaves the old file or the new one, never half of one; a file that does not parse stops the app with a message that names it and is never started over. The release check kills a writer with SIGKILL forty times and reads the file every time.
- **Moving to SQL keeps the data.** `kvOnDb(db)` from `acrylblends/kv/db` gives the same `kv` over a `kv` table of the database `openDb` returned, and `copyKv(source, target)` from `acrylblends/kv` copies a store into another. `npx acrylblends kv import data/kv.json data/app.sqlite` does it from the command line (`--overwrite` replaces keys the table has; it refuses otherwise and changes nothing).
- **`acrylblends add kv` for Blend apps** copies `acryl-kv` (the port) and `acryl-kv-json` (the provider, `kv.json` in the app home) into `src/plugins/`; `acryl-kv-db` is the provider over `db`. A plain Acryl app is told to use `acrylblends/kv/json`.
- The data guide gains "A tiny app: kv": when to use it, the rules for keys and values, and when to move to SQL (more than one process, or a file above a few megabytes, because the whole file lives in memory).

## Things to know

- `create-acrylblends` 0.2.7 depends on `acrylblends` `^0.7.7`. The starters stay on `db`.
- One process owns a JSON file: two writers would overwrite each other. Keys are listed in code point order.
