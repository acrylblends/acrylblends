# 0.3.0

ACRYLBLENDS becomes the public ACRYL framework: generated apps are built on ACRYL's router, shared state and node server (plugins written for Cordis) instead of the small `http`, `server` and `events` plugins of 0.2.x. This release is breaking; the migration is short.

## Breaking changes

1. **`http`, `server` and `events` are removed.** They are replaced by `acryl-router` (`ctx.router`), `acryl-node-server` (the listener, `ctx.nodeServer.url`) and
   `acryl-state` (server-sent streams at `/api/state/<key>/events`). The routes of your app and of every plugin the agent wrote must move to the router API.
2. **The `app` template is now `blank`.** `acrylblends init` takes `--template blank|todo|agent`. `--agent` still means `--template agent`, and `--no-agent`
   still means `--template blank`, so existing scripts keep working.
3. **Rows in `blend.yaml` change.** `http` becomes `acryl-router`, `server` becomes `acryl-node-server`, and `events` is gone (add `acryl-state` where you want
   streams). A generated app now also depends on `@deepseek-ai/schemastery` at run time (the router uses it to validate).
4. **`GET /events` is gone.** The same changes are streamed from state cells: `GET /api/state/tasks/events` and `GET /api/state/extensions/events`, and read at
   `GET /api/state/tasks` and `GET /api/state/extensions`.
5. **Node 22.19 or newer**, as in 0.2.0. The framework plugins run as TypeScript source under Node's type stripping, with no build step.

## Migrating a route: three lines

An extension or a plugin of your own that registered a route on `http` changes like this:

```ts
// 0.2.x
export const inject = ['http']
ctx.effect(() => ctx.http.route('GET', '/hello', () => ({ body: { text: 'Hello' } })))

// 0.3.0
export const inject = ['router']
ctx.router.get('/hello', (c) => c.json({ text: 'Hello' }))
```

A route registered through the plugin's own context is removed when the plugin is unloaded, so the `ctx.effect` wrapper is no longer needed. The rest of the
old handler shape maps directly: `{ status: 404, body }` is `c.json(body, 404)`, the request body is `await c.req.json()`, a path parameter is `c.param('id')`,
and `ctx.http.handle(...)` in a test is `await ctx.router.request('/hello')`.

For an existing app the simplest path is to create a new one with `npx acrylblends init my-app --template blank` (or `agent`), then move your routes and your
own plugins over.

## New

- **The ACRYL framework in the library:** `acryl-router`, `acryl-router-http`, `acryl-node-server`, `acryl-state` and `acryl-inspect` are vendored from ACRYL as they
  are. A sync script copies them with their tests and records the commit and a digest in `upstream.json`; `pnpm run verify:framework` fails when a copy was edited. Their text is in [framework/](../framework/README.md), also generated from ACRYL.
- **The `todo` template:** `npx acrylblends init todo --template todo` gives a todo list built only on the router and state, with CRUD, a page, a server-sent stream and
  a file that keeps the list across restarts. It is ACRYL's reference app, copied as it is.
- **State cells for the agent app:** the latest tasks and the installed extensions are cells, readable and streamable on the router.
- **A fix in extensions:** a plugin installed while the app runs can now read a service as a property (`ctx.router`), not only with `ctx.get`.
- **The offline agent and the model prompt** write router plugins.
- **Docs in one tree** (`docs/framework`, `docs/agent`, `docs/blends`).

## Unchanged

`instance`, `settings`, `extensions`, `builder`, `agent`, `openai`, `sandbox`, `tasks`, `manifest` and `save` keep their behavior. `blend.lock.json` (format version 3)
and the registries are as in 0.2.0.
