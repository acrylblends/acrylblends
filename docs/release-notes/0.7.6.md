# 0.7.6

The dependency rule: app code takes a port, and one file opens the database.

## New

- **`acrylblends check-deps`.** Fails when a file of the app imports a database driver (`node:sqlite`, `pg`, `postgres`, `@electric-sql/pglite`, `better-sqlite3`, `mysql2` and the like), an opener (`acrylblends/db/sqlite`, `acryl-db-sqlite`), or `electron` outside `src/plugins/desktop`, other than the one file the app names in `package.json` as its opener (`"acryl": { "opener": "src/db.ts" }`). It names the file and the line. Comments and strings are not imports.
- **The templates run it.** `notes` and `chat` declare `src/db.ts` as their opener and run the check in `npm test` and `npm run check`; `nodejs` runs it with no opener, so it refuses any database import. Their `AGENTS.md` states the rule for the coding agent.
- **Blend apps.** `acrylblends add db` declares `src/app.ts`, where the provider is mounted, as the opener; a plugin that injects `db` and imports `acryl-db-sqlite` fails `acrylblends check-deps`.
- The data guide gains "Why the database is opened in one place".

## Things to know

- `create-acrylblends` 0.2.6 depends on `acrylblends` `^0.7.6`.
- An existing app is not changed. To adopt the rule, add the `acryl.opener` entry and run `npx acrylblends check-deps`.
