# 1.0.6

The desktop app's windows and menu are door verbs: an agent that lives in the app can open a window, drive it, resize it and press a menu item, and cannot end its own session by accident.

## Windows and menu (desktop app)

- **`acryl window list|open|focus|close|resize` and `acryl menu list|click`.** `window open --path /settings` opens a new window on a path of the app and answers its id; `menu click --path "File>New Note"` presses a menu item by the labels `menu list` prints. They are in the CLI, MCP and the in-app agent's tools like every verb. Settings are a path of the app (build them at `/settings`) or a menu item.
- **`--window <id>` on `look` and `act`** drives the page of that window instead of the page used last. Each window tells the door which it is (an `AcrylWindow/<id>` suffix of its user agent), so it works for windows the agent opened itself and for the first one.
- **It works when the window is attached to `npm run dev`.** The door lives in the server, which is another process then. The Electron main process connects to the door the way a page does (over `/api/acryl-door/shell/*`, which needs the run's secret, so no page can open it) and follows the server across restarts.
- **The session cannot be ended by accident.** `window close` on the last window, and a menu item that ends the app (Quit, Close Window on the last window), are refused unless the call says `--force`; `menu list` marks them. Every call is in `.acryl/audit/ui-control.jsonl` with the window id. With no desktop app attached the verbs answer one line: `no desktop window is attached; run npm run desktop`.
- A new gate, `pnpm run verify:desktop`, runs all of it in a real Electron (attached to a dev server, the app's own server, a dev restart, the guards); CI runs it on Linux under a virtual display and on Windows. Design: [the Electron adapter](../plans/electron-adapter.md).

## The agent template

- `AGENTS.md` tells the in-app agent how to drive the app it builds (`look`, `act`, a path the app does not serve answers `404 at /nope` and the window shows a 404 page, the window and menu verbs, the `--force` caution) and to build settings as a page at `/settings`.

## The package

- **A clean tarball.** 1.0.5 was packed from a working tree that held 95 stray `plugins/acryl-router/src/**/*.d.ts` files (declarations beside their sources; inert, but every new app received them). 1.0.6 is packed from a fresh clone of the release commit, and `verify:tarball` now fails on a declaration file beside its source.
- `packages/cli/lib` (build output) is no longer tracked in the repository; a fresh clone builds and packs the same tarball.

## Upgrading

`npx acrylblends@latest upgrade` brings the door, the router and the desktop shell. An agent-template app's own `AGENTS.md` is its own file: copy the "Drive the app you build" paragraph from a fresh `npm create acrylblends@latest my-app agent` if you want the in-app agent to know the new verbs.
