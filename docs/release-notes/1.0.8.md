# 1.0.8

Two windows of the desktop app, and the Settings the workshop's menu step needs.

## Two live windows no longer stall

- **The cause.** A browser lets a page hold six connections to one host, across all the windows of the app, and the door's channel, the panel's follow of a run and a board's own state were each an event stream held for as long as the page was open: two windows made six, and then every request of either window (the door's answers, Stop) queued forever while the server answered `/health` in a millisecond. 1.0.7's fix covered pages the browser kept after they were left, not two live ones.
- **The fix.** The door's page channel and the panel's runs now travel over a **WebSocket**, which is not one of the six: a page opens it at once however many streams are open, and the answers go up the same socket (a request would queue). The event stream stays as the fallback (a server without the `ws` package, a proxy that cannot upgrade), and the page says so once in the console. A WebSocket has no CORS, so the upgrade is refused unless its `Origin` is exactly the app's own (a page on another port, a web site, a program that sends none are all refused, with tests); the panel's socket also needs its token as the first frame. `ws` is a development dependency of the door, so new apps have it. Checked in a real Chrome with six connections held (the door and the panel still answer; kept to the stream, the look fails in seconds with a reason) and in a real Electron with two windows that hold six streams between them.
- **Streams are the app's to count too.** The agent template's `AGENTS.md` tells the in-app agent to keep to two event streams a page; the state client still opens one per cell (a ticket on the 1.1 list), and the panel's width over a page's fixed elements is another.

## Desktop

- **A Settings item.** The `agent` template serves a `/settings` page (the appearance: system, light or dark, kept in the browser) and the desktop app's menu has a Settings item (Cmd+, on macOS, in the application menu; Ctrl+, in File elsewhere) that opens it in a window, or focuses the window that shows it. `acryl menu click --path "File>Settings..."` does the same; an app without a `/settings` page gets no item. The real-Electron gate presses it and changes the setting through the door.
- **`window open` cascades.** A new window sits a step down and to the right of the one it was opened from, not exactly on top.

## Small

- The panel's disabled buttons look disabled (Send kept its dark style while a run went).
- The preflight names what each agent needs (`pi (DeepSeek key found)`, `codex (be logged in: codex login)`).
- The panel's refusal of a driver says why: a terminal driver (pick it in the panel), an agent that is not on the PATH, pi without a key.

## Upgrading

`npx acrylblends@latest upgrade` brings the door, the panel and the desktop shell; run `npm install` for `ws`. The `agent` template's `src/routes.ts` (the `/settings` page) and `AGENTS.md` are your own files: copy them from a fresh `npm create acrylblends@latest my-app agent` if you want them.
