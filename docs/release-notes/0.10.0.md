# 0.10.0

## Added

- **`driver-pty`: a coding agent in a real terminal inside your app.** `acrylblends add driver-pty` (next to `agent-panel`) offers `pty:claude`, `pty:codex` and `pty:pi` in the panel; choosing one shows the program's own interactive terminal (xterm.js) in the app folder, with `.acryl/bin` on its `PATH`, so it builds through the door in its interactive mode. When it installs or removes a plugin the page reloads and the same terminal comes back with its output. Server-sent events down, POST up, no WebSocket; replay from `Last-Event-ID`. Every process is started in one effect and ended with the plugin (the process group on macOS and Linux). Development only. See [the plugin library](../plugins.md#driver-pty).
- **The panel's drivers are a registry.** Each driver is a `chat` or a `terminal` session; the app's agent and the headless coding agents are chat drivers, and other plugins can add drivers (`ctx.drivers.register`, inside `ctx.effect`). A plugin that injects `drivers` waits until a panel is mounted.
- Gates: `verify:driver-pty` (headless Chrome, a scripted program in the PTY), `pnpm run test:driver-pty` with a real PTY on Linux, macOS and Windows, and `verify:packed` adds the panel and the driver with the installed command.

## Things to know

- `node-pty` (MIT) is installed by `acrylblends add driver-pty`; xterm.js 6.0.0 and its fit addon 0.11.0 are vendored in the plugin with their licenses (see `THIRD_PARTY_NOTICES.md`).
- `GET /api/agent-panel/session` now answers `drivers` as `[{ name, kind }]` instead of a list of names.
- `create-acrylblends` 0.4.0 depends on `acrylblends` `^0.10.0`.
