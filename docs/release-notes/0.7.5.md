# 0.7.5

A database for the starters: the `db` port, numbered migrations, and the notes and chat templates on them.

## New

- **`acrylblends/db` and `acrylblends/db/sqlite`.** `openDb({ path, migrations })` opens one SQLite file (its folder is created), enforces foreign keys, applies the numbered SQL files in `migrations/` once, in order, in one transaction, and returns `{ db, close }`. `db` is the same small interface a Postgres provider will serve: `exec`, `run` (resolves `{ changes }`), `get`, `all` and `transaction`, every call a promise, `?` bindings. The port has no `close`: the code that opened the database closes it. 105 subpaths now. See the new [data guide](../framework/guides/data.md): the port, migrations, a table for choosing a store, transactions, tests, shutdown, and writing SQL that moves to Postgres.
- **The `notes` and `chat` templates use it.** `migrations/001-notes.sql` and `migrations/001-chat.sql` hold the schema, the stores take a `Db` and `await` it, `src/app.ts` opens the database (`data/notes.sqlite`, `data/chat.sqlite`, or `$NOTES_DB` / `$CHAT_DB`), `src/index.ts` closes it when the process is told to stop, and the tests open `:memory:` with the real migrations. To change the schema, add the next numbered file; never edit one that has run. Neither template imports `node:sqlite` any more.
- **`acrylblends add db` for Blend apps.** Copies `acryl-db` (the port) and `acryl-db-sqlite` (the provider) into `src/plugins/`: mount the provider after `instance` with a `migrations` folder, and any plugin that declares `inject: ['db']` gets the same `db`. A plain Acryl app is told to use `acrylblends/db/sqlite`.
- The desktop shell of a plain app calls the app module's `close` (when it exports one) after the server stops.

## Changed

- A new `notes` or `chat` app keeps its file in `data/` (it was `notes.db` and `chat.db` in the app folder). An existing app is not touched; to move one, put its file at the new path, or set `NOTES_DB` / `CHAT_DB` to the old one, and add its tables as `001-*.sql` (the migration runs `CREATE TABLE`, so start from an empty file or write the migration with `IF NOT EXISTS`).
- The forms and sessions, deploy and create-acrylblends pages describe the new files and variables.

## Things to know

- `create-acrylblends` 0.2.5 depends on `acrylblends` `^0.7.5`.
- Postgres, `kv` and `durable` are planned, not released; the data guide says which parts are available.
